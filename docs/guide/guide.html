1Introduction

The BMS Suite is a set of editing tools for Falcon BMS 4.38. It covers the whole life of a theater: the terrain, the objectives on it, the user interface art, the campaigns, the 3D models and the database records that tie them together. One main menu starts every program on the theater you are working on.

ProgramWhat it is for
TerrainToolBuilds the New Terrain of a theater from free real-world data (elevation, water, coastlines, land cover, forests, roads), prepares the input for Terrain Builder, turns its output into the files BMS needs, builds the theater and installs it.
Objective StudioEverything inside the objectives: airbases and their layouts, pieces, parking and runway points, bridges, coastal objects. Replaces an airbase with a better one, previews it in 3D, builds the objects and installs them.
Art EditorThe user interface art: the BMS screens as the theater shows them, team flags, banners and menu backgrounds, campaign pictures, small maps, squadron patches, medals, texts of Theater.irc, fonts and sounds.
Campaign EditorCampaigns (.cam) and Tactical Engagements (.tac): objectives, owners and links, units, squadrons, air defense, stations and ILS, campaign AI, TE lists, campaign terrain.
Model Editor3D models with a DirectX view (PBR materials, normal maps, shadows), DOFs, switches, weapon slots, Parent.dat checks, and the theater database (aircraft, vehicles, weapons, sensors...).
Database InterchangeCopies bases, ground objective layouts, aircraft, vehicles and weapons from one BMS 4.38 theater to another with everything they need, renumbered for the destination.
4.37 Units ConverterConverts aircraft, helicopters, vehicles and weapons of an old BMS database (a 4.37 installation, an add-on or just its objects folder) into a theater of BMS 4.38: 3D models, hardpoint lists, weapons, squadron types, the TE list and the names, with backup and restore.
Sim EditorFor a theater made with TerrainTool: its own Sim files (SimOverrides), the database changes (DbEdits.txt) and the check of the air defence systems in its campaigns.

Three rules behind every program

  1. BMS is read, not changed, while you work. Your edits are kept in the program's own work folder. Only the Install (or Save into BMS) step writes into the BMS folders, and only after you confirm.
  2. Every file that is replaced is saved first. Each program keeps its backups and has a Restore that puts the old files back. The main menu lists all backups.
  3. The Korea originals are never touched. The Korea art (Data\Art) and the shared objects folder of BMS (Data\Terrdata\objects) are only read: they are the master copies every theater falls back on. The only exception is the 4.37 Units Converter, which adds an old add-on's own 3D models and textures there with free numbers (nothing is replaced, and its Restore removes them).

How the programs fit together

The four programs of Build a theater follow the order in which a theater is made: the terrain first (TerrainTool), then the objectives on it (Objective Studio), the interface art (Art Editor) and finally the campaigns that use all of them (Campaign Editor). Model Editor and Database Interchange work on any theater at any time; Sim Editor works on a TerrainTool project.

You do not have to build a theater from scratch to use the suite: every program also opens a theater that is already installed in BMS (Korea, Israel, any add-on) to change it.

2Installation and first start

Requirements

  • Windows 10 or 11, 64-bit.
  • Falcon BMS 4.38 installed.
  • The .NET 8 Desktop Runtime (x64), free from Microsoft: dotnet.microsoft.com/download/dotnet/8.0. If it is missing, Windows offers to download it the first time you start a program.
  • Disk space: the programs need little, but TerrainTool's source data and terrain files take many gigabytes for a large theater.

Install

  1. On the GitHub page of the project open Releases and download BMSSuite-<version>.zip.
  2. Unzip it into a folder you can write to, for example C:\BMS Suite. Do not use Program Files and do not put it inside the BMS folder: the programs keep their settings, work folders and backups next to themselves.
  3. Start BMSSuite.exe.

What is in the folder

PathContents
BMSSuite.exeThe main menu.
Programs\<program>One folder per program (TerrainTool, ObjectiveStudio, ArtEditor, CampaignEditor, ModelEditor, DatabaseInterchange). Each keeps here its Settings, its work folders (Theaters, Projects, Transfers...) and its backups.
Data\NaturalEarthWorld coastlines, lakes and borders (public domain) used for maps.
SettingsSettings of the main menu (created at the first start).

First start

The main menu finds Falcon BMS by itself (from the Windows registry). If it cannot, the first chip at the top shows BMS NOT FOUND: click it and choose the BMS Data folder, the one that contains Terrdata, Campaign and Art.

Each program remembers the BMS Data folder the first time you choose it (field BMS Data folder at the top of its window, with Browse...).

Before you edit anythingMake a copy of your BMS Data folder, or at least of the theater you are going to change. The programs back up every file they replace, but a copy of your own is the safest way back, especially the first time.

Updating

Download the new zip and unzip it over the old folder. Your settings, work folders and backups are kept, because they are not in the zip.

4Safety: backups and restore

All programs follow the same pattern, so you always know what is written and how to undo it.

StageWhat happensWhere
EditChanges stay in the program. Nothing is written yet.Memory
SaveYour edits are written to the program's work folder (for installed theaters) or to the TerrainTool project. BMS is not touched.Theaters\<theater>, Projects\<project>
BuildThe program makes the final files from your saved edits, again outside BMS.Output of the work folder
InstallOnly new or changed files are copied into BMS. Every file that is replaced is copied first into a backup folder named with date and time.BMS; backup in Output\BmsBackup, Backup or Transfers\Backups
RestorePuts back the files of the backup you choose. Files that the installation added new are removed where the program knows them (Database Interchange) or listed for you to remove.BMS

Good habits

  • Close BMS before any install or save into BMS. BMS keeps some files open and would not see the new ones anyway.
  • Copy your BMS Data folder (or the theater's folder) the first time you install into it.
  • After installing, start BMS and check the theater (the objects, the campaign, the art) before going on with the next change.
  • When a program installs objects or a terrain, it deletes the caches BMS rebuilds by itself (for example the campaign terrain cache), so BMS uses the new data at the next start.
Restoring an older stateRestore the backups newest first. If you restore the folder of a later install while an earlier one is still applied, the result is a mix of the two.

5TerrainTool

TerrainTool builds the New Terrain of a theater from free real-world data and turns it, together with the objects, art and campaigns, into a theater ready for BMS. It replaces the manual QGIS and Photoshop work around Terrain Builder. Its work is kept in a project (.ttproj) in Projects\<name>; it never writes into BMS, Korea, Terrain Builder or the old theater except in tab 9, after confirmation.

The window has nine tabs in working order. The buttons at the top create or open a project, save it, and open Objective Studio and the Campaign Editor on the same project. The log at the bottom records every step.

1 · Theater & projection

  • Size (km) and Map size (pixels) of the theater (e.g. 2048 km, 32768 px = 62.5 m per pixel), Center latitude / longitude, Min / Max height, the Name in BMS.
  • Choose area on the world map... picks the area for a new theater; Fit center to airbases centres the theater on the real positions of its airbases; Compare with Korea checks the parameters against the Korea theater; Write Theater.txt.
  • Computed values shows resolutions, theater corners, the airbases outside or close to the edge.
  • Folders: project folder, the Korea NewTerrain (read only, used as reference), Terrain Builder and, when converting an older add-on, the old theater (read only).

2 · Airbases & check map

The table lists every airbase of the theater with its real latitude/longitude (from OurAirports) and, for an old add-on, its old in-game position. Tier sets the build priority (Main, Secondary, Micro) and Server marks the neutral airbase for the PvP server aircraft. Bases marked to verify need the real position typed in by hand. Load CSV / Save CSV exchange the list as a file. On the map: wheel = zoom, drag = pan, double-click = fit view.

3 · Source data

TerrainTool downloads, for the theater area only: Copernicus DEM (30 m or 90 m heights), OSM water polygons and coastlines, Geofabrik OSM extracts (inland water, roads, bridges), GEBCO sea depth, ESA WorldCover land cover, Hansen tree cover and NASA Blue Marble colour. Downloads resume where they stopped and skip files already present. Website and Folder open the source and the local copy.

4 · Processing

Each row is a step: heightmap, watermap, coastline and coast points, ocean depth, tree cover / forest density, land cover, roads and bridges, satellite colour map. Choose an Output size: a small test size (1024 or 4096) takes minutes and shows a preview; the full size takes longer and needs several GB. The results go to Output\TB_Input, ready for Terrain Builder.

5 · Terrain files

Set the Terrain Builder output folder, then run the jobs: they read Terrain Builder's RAW files and write the DDS textures and final RAW files into Output\NewTerrain with the names BMS expects (depth map, culling map, global alpha, height maps, land cover map, forest map...). Extra tools: Photoreal tile editor..., Terrain preview..., Water DEM..., Analyse Terrain Builder output, Probe points (diagnostic)....

6 · Terrain check

7 · Theater content

2D map makes the theater map BMS shows in Instant Action, TE and campaign from the satellite colour map; Objects & campaigns converts the objects and campaigns of an old add-on; UI art prepares the art (then refined in the Art Editor). The theater's own Sim files, the database changes and the SAM check are in the Sim Editor (chapter 12, button Sim Editor at the top of TerrainTool).

8 · Build theater

The table says which parts are ready and which are missing, with a button to go where each one is made. Build theater puts everything together in Output\Install and writes a new theater definition. Nothing is written into BMS here.

9 · Install into BMS

Install everything... copies the built theater into BMS (only new or changed files; every replaced file is first saved in Output\BmsBackup). The other buttons install one part at a time: terrain and water maps, photoreal tiles, objects and campaigns, UI art, theater Sim. Restore a backup... puts back the files saved before an installation; Remove from BMS's theater list... hides the theater from BMS; Check the terrain installed in BMS verifies the installed files.

6Objective Studio

Objective Studio shows what is inside the objectives of a theater: airbases, layouts and their pieces, parking and runway points, bridges. It works on a theater installed in BMS (Korea, Israel, any add-on) or on a TerrainTool project (a theater being converted). For an installed theater it only reads BMS: your edits stay in Theaters\<theater> until you build and install them.

The three steps

  1. Edit objectives – Objective editor... (the map, Figure 6.3), Fly over objectives... (a 3D flight over the objectives one after the other) and Optimize bridges... (moves bridge points where they open the river crossings for ground units). Edits are saved in the work folder.
  2. Build objects – applies your saved edits to a copy of the theater's objects in the work folder. Nothing else is changed.
  3. Install into BMS – copies into the theater's folders only the built files that changed; every replaced file is saved first. Restore a backup... puts them back. The campaign files are updated to the new objectives at the same time.

Other tools: Model textures... (the textures of a 3D model) and Open output folder.

Objective editor

On the left, the list of objectives (filter by type, search by name, Only edited); below, the data of the selected objective and the editing buttons. On the right, the map with the pieces of every layout drawn over the ground photo. The checkboxes at the top show or hide buildings, taxiways, parking and defence points, names, links, hierarchy, BMS water and the protractor.

Puts a complete base on the airbase: one of the BMS 4.38 Korea bases (with its taxiway asphalt model) or a base of this theater, including those imported with Database Interchange. The Art Editor changes the user interface art of a theater. A theater's art folder (the artdir of its .tdf) keeps only the files the theater changes; everything else comes from the Korea art in Data\Art, the master of every theater, which the editor never changes. The editor shows the art exactly as BMS shows it: the theater's image if it has one, otherwise the Korea one ("BMS default").

8Campaign Editor

The Campaign Editor opens the campaigns (.cam) and Tactical Engagements (.tac) of any installed theater, or of a TerrainTool project.

Double-click a file (or Open in the campaign editor). Empty editor opens without a file. For a project: Apply object changes brings the campaign up to date with the objectives edited in Objective Studio, Install campaign files into BMS... copies them into the add-on, Campaign terrain (.thr)... opens the terrain window (Figure 8.6).

The editor window

  • Left – tabs Objectives, Units, Teams, Packages, Squadrons with search and filters.
  • Map – background (terrain texture, political map), icons (BMS icons), what to show (links, units, names, front lines, routes, air defence rings).   • Right – Properties of the selection and Map legend.
  • Validation – errors, warnings and notes; double-click a row to see it on the map.

9Model Editor

10Database Interchange

Database Interchange copies things from one BMS 4.38 theater to another, with everything they need, renumbered for the destination. Two tabs: bases and ground objective layouts, and aircraft, vehicles & weapons (aircraft, helicopters, ground vehicles, ships, weapons and unit types, with their aircraft data, sensors, radars, hardpoint lists, rocket pods, squadron stores and 3D models; new weapon numbers are added to the same racks in BmsRack.dat). Flight models and the other Sim files are not copied.

  1. Choose From (the source theater) and To (the destination). The destination must have its own objects database: the shared objects of BMS (Korea) are never written and are marked as not writable.
  2. Select one or more layouts on the left (search by name or OCD number; Ctrl / Shift+click for more).
  3. Make plan (nothing written): shows what will be copied and with which numbers – the layout folder with a new OCD number, a new Class Table entry, every kind of piece (reused if the destination has the same one, otherwise new records), the 3D models and textures needed (reused or copied).
  4. Close BMS and press Install into the destination.... Everything replaced is first copied to Transfers\Backups\<time> with a list of what was added.
  5. To use the imported base: Objective Studio → the destination theater → select the airbase → Replace base... → choose the new base (Source "This theater") → Save edits, Build objects, Install into BMS....

Restore... undoes an installation: it removes what it added and puts back what it replaced.

Shared 3D modelsWhen the destination takes its models from the shared BMS objects folder (as most add-ons do), no model or texture is copied: the plan tells you which pieces would look different and which models are missing.
Old add-onsAircraft and vehicles of an old BMS database (4.37 or older) are converted with the 4.37 Units Converter (chapter 11): Database Interchange is for 4.38 → 4.38.

114.37 Units Converter

The 4.37 Units Converter brings aircraft, helicopters, ground vehicles, ships and weapons of an old BMS database (BMS 4.37 or older) into a theater of a BMS 4.38 installation. Everything is done in its window, from start to end, and a backup is made before every installation: Restore... puts the theater back as it was.

  1. 1 · Old database: a BMS 4.37 installation (one entry per theater), an add-on folder (with Terrdata\Objects) or just an objects folder with Falcon4_CT.xml.
  2. 2 · BMS 4.38 theater: the BMS 4.38 installation and the theater to convert into. It must have its own database: BMS's own Terrdata\objects (Korea) is never written.
  3. Find what can be converted lists what the old database has and the theater has not, by name. Tick Convert. For aircraft and helicopters set the Name in the TE and the aircraft whose picture and icon the TE list shows (TE picture and icon like). Source model: BMS 4.38 has a different 3D model with the same number; tick it to bring the old one.
  4. Check the conversion (nothing written) shows the plan step by step: 1 3D models and textures (added with a free number when BMS has another one with theirs, never replaced); 2 hardpoint lists, compared by their weapons (an old add-on often changed BMS's lists keeping their names); 3 weapons (BMS's ones with the same name, the others added); 4 aircraft (free class numbers, first year of service, the BMS 4.38 flight model chosen in Flies like); 5 squadron and flight types; 6 the line in the theater's TePlanes.lst and the name in its interface files.
  5. Close BMS and press Convert and install.... Then start BMS: Tactical Engagement → New, the aircraft are in the squadron list.
Flight modelsFlight models (Sim\Acdata) stay BMS 4.38's: they are never copied nor changed, as the BMS developers ask. Each aircraft gets a BMS 4.38 flight model, column Flies like: it gives the racks and pylons of each hardpoint and where the wheels touch the ground. The list puts first the ones with racks on every hardpoint the aircraft uses, the same pylons left and right, and the aircraft's own wheels on the ground (it tells how many cm above or into the ground); the one of the same name is suggested when it is as good. Pylon models of another aircraft may look different from the old add-on's: if weapons look wrong in BMS, Restore, pick another one and convert again.
Authors3D models and textures of an add-on belong to their authors: convert them for yourself, ask them before you share a theater with them.

What was converted is listed in the theater's objects folder (UnitsConverter.csv, UnitsConverter_picks.csv). For a theater built with TerrainTool, Install objects... rebuilds the theater's database and converts these again by itself.

12Sim Editor

The Sim Editor works on a TerrainTool project (it opens on the project from the Sim Editor button of TerrainTool, or asks for it: Recent projects → Open, or Browse project...). Everything it changes goes into the theater with Run Objects (Objective Studio) and Build theater (TerrainTool), then the install: BMS's own files are never changed.

The theater's own Sim

  • Copy a BMS Sim file to SimOverrides...: pick files of BMS Data\Sim (for example Misdata\SA-2F.dat); they are copied into the project's SimOverrides folder with the same path. Edit them there (Open SimOverrides). The flight models (Acdata) are not copied nor edited: they stay BMS's, as the BMS developers ask.
  • The line under the buttons says whether the theater has its own Sim and which files it changes. Build theater makes NT\Sim = a full copy of BMS Data\Sim plus your files.
  • Install theater Sim into BMS... (BMS closed) copies it into the theater's folder and sets simdatadir in its .tdf; replaced files are saved in Output\BmsBackup. The same button is in TerrainTool, tab 9.

Database changes (DbEdits.txt)

On the right, one change per line: TABLE Num Field Value # comment (for example UCD 161 ElementCount_1 3), or COPY TABLE From To for a new record with the next free number. Save checks the format first; Reload reads the file again. They are applied by Run Objects on top of BMS's database, so they survive BMS updates. A COPY onto a number that a newer BMS uses stops Run Objects with the next free number to use.

Check SAM systems & positions

Reads the theater database (with DbEdits.txt, also the changes not saved yet), the Sim radar data and every campaign and TE of the project. The upper list shows each air defence battalion type: launchers, missiles each, missile, radars, rate of fire, the points it needs and how many battalions the campaigns have. Select a row to see its battalions below, with the point list BMS gives each one on its objective and whether all vehicles fit. All SAM types shows also the types not used; Only problems keeps the battalions with vehicles off the base points.

13Typical workflows

A. Change an airbase of an installed theater

  1. Main menu: select the theater, open Objective Studio (it opens on that theater).
  2. Objective editor...: find the airbase, move or rotate it, or use Replace base.... Check it in 3D preview. Save edits.
  3. Main window: Build objects.
  4. Close BMS, Install into BMS....
  5. Start BMS and look at the base. To go back: Restore a backup....

B. Bring a base from another theater

  1. Database Interchange: From the source theater, To yours; select the layout; Make plan; read it; Install into the destination....
  2. Objective Studio on your theater: Replace base... on the airbase, Source This theater, choose the imported base, OK, Save edits.
  3. Build objects, Install into BMS....

C. New art for a theater

  1. Art Editor → Open... → the theater (or New theater art...).
  2. Replace flags, backgrounds, campaign pictures and texts; check the screens in Screens (visual editor).
  3. Check, then Save (or Copy into a theater... for art made elsewhere). Restart BMS.

D. Edit a campaign

  1. Campaign Editor → the theater → double-click the .cam or .tac file.
  2. Change owners (Paint owner), links, units, squadrons; use Air defense plan... and Deploy divisions... for the start of a campaign.
  3. Validate and fix the errors (double-click a row to see it on the map).
  4. Close BMS, Save. Start the campaign in BMS to check it.

E. Build a new theater

  1. TerrainTool → New project...: choose the area on the world map, size and name (tab 1); check the airbases (tab 2).
  2. Download the data (tab 3) and process it, first at a test size (tab 4).
  3. Run Terrain Builder on Output\TB_Input, then make the terrain files (tab 5) and check them (tab 6).
  4. Objects in Objective Studio (Open TerrainTool project...), art in the Art Editor, campaigns in the Campaign Editor, the 2D map in tab 7.
  5. Build theater (tab 8) and Install everything... (tab 9).

Every button of these workflows, in order: chapter 14 (a new area) and chapter 15 (converting a 4.37 add-on).

14Step by step: a new theater from scratch

This chapter makes the terrain of a theater for an area that BMS does not have yet: heights, water, land cover, forests, satellite colours, photoreal tiles and the 2D map. Every button and option is listed in the order you press it.

What is not supported yetFor a new area the suite makes the terrain and the 2D map. It does not make yet the objectives (airbases, cities, bridges and their links), the campaigns and the theater definition (.tdf) of a new area: these three are taken from an existing add-on, which a new area does not have. So Build theater (tab 8) stops with “Theater definition: Missing” and the theater cannot be installed into BMS and flown yet. What you can do today is everything up to tab 7, and look at the result with Terrain preview..., Photoreal tile editor... and Terrain check. The cities and targets chosen on the world map are kept in the project for when the objectives can be made.

Before you start

  • BMS 4.38 installed (the Korea theater is used as reference, only read).
  • Free disk: plan for tens of GB (downloads, intermediate files, photoreal tiles), more for a 2048 km theater and for the Sentinel-2 photoreal. Put the suite on a fast disk.
  • A good internet connection: the downloads are several GB; the Sentinel-2 photoreal of a whole theater takes hours the first time.
  • Terrain Builder is not needed: its Water DEM mode is rebuilt in TerrainTool (step 6). You can still use it if you want to compare.

1 · Create the project

  1. Main menu → TerrainTool.
  2. Press New project... at the top. In the folder window (“Choose or create an empty folder for the new project”) create a new folder inside TerrainTool\Projects, for example Projects\Balkans, and select it. A folder inside BMS, Korea, Terrain Builder or an old theater is refused.
  3. The New project window asks “Which airbases should the new theater start with?”. Choose Choose the area on a world map – airbases from OurAirports: and press Choose area....

2 · Choose the area on the world map

  1. Size (km): 1024 (like Korea) or 2048 (like Mideast). BMS supports only these two.
  2. Place the square: drag it to move it, drag elsewhere to pan, wheel to zoom, double-click to put the square there. You can also type Centre latitude and Centre longitude. Keep the places you care about well inside: Distance from edge (km) shows the closest airbase to the edge.
  3. Airbases: tick Military airbases and/or Civil airports; Also small airfields (if the runway is long enough) with the Shortest runway (m) you accept (1830 m = 6000 ft by default); Main airbases (most) sets how many become Main tier, the others Secondary.
  4. Show country borders and names helps placing the square.
  5. Cities & targets (kept for later): Cities and Towns with “from (inhabitants)”, then Ports, Power plants (and nuclear) with “smallest plant (MW)”, Refineries, Military bases and barracks (named). Cities and towns follow the square at once; for the others press Search OpenStreetMap in this area after placing the square (it can take a few minutes).
  6. Press Use this area, then Create project in the New project window.
The other two choicesEmpty list – I will add the airbases myself in tab 2 starts without airbases (you set the area in tab 1). Import the airbases of a theater installed in BMS takes the airbases of a BMS theater: choose the BMS Data folder (Browse...) and the Theater; with Also use its size, centre and heights (tab 1) the new terrain is laid on that theater's area (this is for conversions, chapter 15).

3 · Tab 1 · Theater & projection

  1. Check Project name. It is used in the names of the intermediate files: do not change it once the work has started.
  2. Size (km) and Map size (pixels): keep 62.5 m per pixel, the BMS standard: 1024 with 16384, 2048 with 32768.
  3. Center latitude (°N) / Center longitude (°E): set by the world map. Fit center to airbases centres the theater on its airbases; use it only for a new theater, before downloading.
  4. Min height (ft) / Max height (ft): below the lowest sea floor you need and above the highest mountain of the area (e.g. −1500 / 19000 for the Middle East). Too narrow a range cuts the terrain; too wide wastes precision.
  5. Name in BMS and Description in BMS: what the BMS Launcher will show.
  6. Folders: Project folder is already set (Open opens it). Korea NewTerrain (read-only): press ... and choose Data\TerrData\Korea\NewTerrain of your BMS 4.38. Terrain Builder: only if you have it. Old theater (read-only): leave empty for a new area.
  7. Look at Computed values (resolution, corners, airbases near the edge) and press Compare with Korea: every line should be OK or explained.
  8. Press Write Theater.txt, then Save (top).
ProjectionA new theater is always made on the standard transverse Mercator centred on the theater, the projection BMS uses for latitude/longitude (DED, DTC, Tacview). Switch to standard projection... is only for old add-ons converted with their own georeference.

4 · Tab 2 · Airbases & check map

  1. Look at the list: Name, Country, ICAO, Lat, Lon, Tier, Status. Filter with Tier (All, Main, Secondary, Micro, Server) and Only to verify.
  2. For every row with Status to verify type the real Lat/Lon (e.g. from the runway centre on a map) and set Status to ok.
  3. Set the Tier: Main first, Secondary, Micro only if needed; at most one Server (the neutral base of the PvP server aircraft). Delete the bases you do not want.
  4. On the map check that every dot is on its airport: wheel = zoom, drag = pan, double-click = Fit view.
  5. Save CSV (writes airbases.csv in the project), then Save.

5 · Tab 3 · Source data

  1. Tick the datasets (the Present column says what is already there):
    • Copernicus DEM GLO-30 (30 m, best) or GLO-90 (90 m, smaller download) – heights.
    • OSM water polygons and OSM coastlines – sea and coast.
    • Geofabrik OSM extracts – lakes, rivers, roads, bridges.
    • GEBCO derived polygons – sea depth.
    • ESA WorldCover 10 m – land cover.
    • Hansen tree cover 2000 – forests.
    • NASA Blue Marble NG (July) – satellite colour.
    • Leave SRTM / ALOS unticked: they need a login and are only for Terrain Builder's own DEM mode.
  2. Press Download selected. You can Cancel and start again at any time: downloads resume and skip the files already present. Tiles entirely at sea are marked “not available”: this is normal.
  3. Press Refresh at the end: every ticked row must be present.

6 · Tab 4 · Processing

  1. Output size = 4096 (quick test). Select all, then untick the two Sentinel-2 rows. Press Run selected. In a few minutes the Preview shows each result: check the coast, the lakes, the mountains.
  2. If the test looks right: Output size = Full size (map pixels), same rows ticked, Run selected. The steps are, in order: Heightmap (DEM), Watermap, Coastline + coast points, Ocean depth, Tree cover / forest density, Land cover, Roads + bridges, Satellite colour map. Results go to Output\TB_Input.
  3. Last result must say OK on every row. Open output folder shows the files.

The Sentinel-2 rows are run later, in step 9.

7 · Water DEM (tab 5, button Water DEM...)

  1. Tab 5 · Terrain files → Water DEM....
  2. The inputs are filled from tab 4: DEM (16-bit RAW, feet), Watermap (8-bit RAW), Coastline (8-bit RAW), Coast points (SHP). Output folder = Output\WaterDem.
  3. Parameters (keep the defaults, they are Terrain Builder's): Water depth ft 40, Hidden water ft 300, Culling km 10.5, Threads (all cores but one).
  4. Press Check again: the Checks list must be green (disk space, sizes, RAM). Optional: Check coasts and islands / Check islands (OSM).
  5. Press Run Water DEM (a few minutes). The log ends with “DONE”.
  6. Tick Use these water maps for the texture jobs (tab 5) instead of Terrain Builder's Water DEM output and close the window.

8 · Tab 5 · Terrain files

  1. Terrain Builder output folder: leave it as it is (with “Use these water maps” ticked, the water maps come from Output\WaterDem). Press Refresh.
  2. Select all and Run selected. The jobs are: DepthMap_nsrgb.dds, CullingMap_nsrgb.dds, GlobalAlpha_nsrgb.dds, Copy TB RAW outputs, LandCoverMap.raw, ForestMap.raw, GlobalColorMap.dds, ColorMap.dds (water), Photoreal 4K tiles (placeholder tiles from the satellite colour map, ~10 GB), SnowMap*.raw, FFTMap.raw (waves).
  3. Every Last result must be OK. The files are in Output\NewTerrain (Open NewTerrain output).

9 · Photoreal from Sentinel-2 (tab 4)

  1. Tab 4 → Photoreal imagery: Sentinel-2 cloudless 2016 (CC BY) or 2024 (CC BY-NC-SA) (non-commercial, share-alike: fine for a free theater, keep the credit).
  2. Tick only Sentinel-2 photoreal 4K (test area) → Run selected. It makes the tiles around the airbase nearest the centre: look at them in tab 5 → Photoreal tile editor....
  3. Then tick only Sentinel-2 photoreal 4K → Run selected. Hours the first time; it resumes where it stopped. It replaces the placeholder tiles of step 8.
Do not run “Photoreal 4K tiles” againafter the Sentinel-2 step: it would put the placeholder tiles back. If you do, run the Sentinel-2 step again (the downloaded imagery is kept, so it is quick).

10 · Tab 6 · Terrain check and preview

  1. Tab 6 · Terrain check → Project output → Check. Every required file must be OK in Status; Actual and Expected show sizes; Korea compares with Korea.
  2. Tab 5 → Terrain preview...: pick a point on the map, an airbase or lat/lon and fly the free camera over heights, water and photoreal.
  3. Problem areas: write name;lat;lon;radius km lines in probe.txt and press Probe points (diagnostic)....

11 · Tab 7 · 2D map

  1. Tab 7 · Theater content → sub-tab 2D map.
  2. Tick 2D map (campmap) only → Run selected. (“2D map + test points” draws test markers over it: use it only to check, then run 2D map again.)
  3. Tick Theater art (flags, backgrounds, patches) → Run selected: the small maps of the UI on the theater's grid. Open art output folder shows them.
  4. The rest of the art (flags, backgrounds, texts) with the Art Editor (chapter 7) on this project.

12 · Where it stops today

Tab 8 · Build theater → Refresh shows the state of every part. Terrain files and 2D map are Ready; Objects, Campaign and Theater definition are Missing, and Build theater says “The theater cannot be built yet”. Keep the project: when objectives and campaigns for a new area are supported, the work continues from here, without making the terrain again.

15Step by step: converting a 4.37 theater to 4.38

This chapter converts an add-on made for BMS 4.37 (classic terrain) into a BMS 4.38 theater with New Terrain: the terrain is made again from real data, the objectives, airbases and campaigns of the old add-on are carried over, and the result is installed as a new theater next to the old one. The Mideast 4.38 was made this way.

Positions of the old add-onA classic 4.37 theater has no geographic reference: its objectives are on its own grid, which is not the real world. The new terrain is the real world. The conversion moves the airbases onto the real runways (step 6), but cities, bridges and the other objectives stay at their old grid positions: check them in the Objective editor and move the ones that matter. TerrainTool has no window to fit a georeference to an old theater; a project that has one (like the Mideast) carries every position over through latitude/longitude.

Before you start

  • BMS 4.38 installed and started once. A copy of your BMS Data folder (at least TerrData, Campaign, Art and Add-On) before the first install.
  • The old 4.37 add-on, complete, in a folder of its own (the folder with its Campaign, TerrData, Objects, Art...). The suite only reads it.
  • The disk space and connection of chapter 14.

1 · Create the project

  1. Main menu → TerrainTool → New project... → create and select an empty folder in TerrainTool\Projects.
  2. If the old theater appears in your BMS theater list: choose Import the airbases of a theater installed in BMS:, Browse... to the BMS Data folder, choose the Theater. If the line under it says “with position”, tick Also use its size, centre and heights (tab 1), so its campaign and objects stay in place; if it says “names only”, the add-on has no reference and you set the area in tab 1.
  3. If it is not in the list: choose Choose the area on a world map – airbases from OurAirports: and place the square over the same area as the old theater, same size (chapter 14, step 2).
  4. Create project.

2 · Tab 1 · Theater & projection

  1. Size (km) = the size of the old theater (1024 or 2048); Map size (pixels) 16384 or 32768.
  2. Center latitude / longitude: if imported “with position”, leave them. Otherwise put the centre of the old map; Fit center to airbases helps. Do not change the centre after step 4: the old objectives follow the grid, not the coordinates.
  3. Min / Max height (ft), Name in BMS (e.g. “Balkans 4.38”, different from the old theater so both can stay installed), Description in BMS.
  4. Folders: Korea NewTerrain (read-only) → ... → Data\TerrData\Korea\NewTerrain. Old theater (read-only) → ... → the folder of the old add-on. This is what makes it a conversion: objects, campaigns, art and the theater definition are read from there.
  5. Compare with Korea, Write Theater.txt, Save.

3 · Tab 2 · Airbases

  1. Tick Show old theater positions (purple): you see how far each old base is from its real airport (LatOld/LonOld = old position, Lat/Lon = real one).
  2. Only to verify: for each row type the real Lat/Lon and set Status ok. Set Tier and Server as in chapter 14.
  3. Save CSV, Save.

4 · The terrain (tabs 3 to 6)

Exactly as in chapter 14, steps 5 to 10: Download selected (tab 3), Run selected at test size then at Full size (map pixels) (tab 4), Water DEM... with Run Water DEM and Use these water maps..., Select all → Run selected in tab 5, Sentinel-2 photoreal (tab 4), Check in tab 6.

5 · Tab 7 · Theater content

  1. 2D map sub-tab: run 2D map (campmap), then Theater art (flags, backgrounds, patches). Theater art starts from the BMS 4.38 art and adds the old add-on's images; it remakes the small maps of the UI on the new grid.
  2. UI art sub-tab → Open the Art Editor → open this project: Check lists the old images with wrong sizes; replace or Reset to BMS 4.38; Save.
  3. Sim Editor (button at the top of TerrainTool; only if the add-on changed BMS data): write the database changes in Database changes (DbEdits.txt) → Save; Sim files with Copy a BMS Sim file to SimOverrides... and edit them in Open SimOverrides. Press Check SAM systems & positions (tick Only problems) after the objects are built (step 6). Aircraft and vehicles of the old add-on: the 4.37 Units Converter after the install (chapter 11).
DbEdits.txt and new recordsA line COPY <table> <from> <to> must use a number that BMS 4.38 does not use yet. If BMS already has that number, the Objects job stops with “this BMS version already has … Use the next free number”: change the number and every line that refers to it.

6 · Objective Studio: the objects

  1. TerrainTool top bar → Objective Studio (or main menu → Objective Studio → Open TerrainTool project... → the .ttproj; next time: Recent → the project → Open). The window says “TerrainTool project · theater conversion from the old add-on”. Do not open the old theater installed in BMS instead.
  2. Real runways from OpenStreetMap (close the objective editor first): asks OpenStreetMap for the runways of the airbases not in OurAirports and writes airbase_targets.csv.
  3. Run Objects (from the old add-on): builds the theater's objects in Output\Install – BMS 4.38 database with your DbEdits, the old add-on's layouts, airbases moved and turned onto the real runways, your objective edits, leveling. Read the log: it says what was moved, kept and why.
  4. Review coastal moves...: objectives that Run Objects moved out of the water; accept or change them.
  5. Optimize bridges...: moves bridge points where they open river crossings.
  6. Objective editor...: check every Main airbase on the photo; Align to real runway if needed; move cities and bridges that are off; 3D preview; Save edits. A saved edit wins over the automatic move, so only save the bases you really changed.
  7. The Next step box now says “Edits saved after the last Run Objects”: press Run Objects (from the old add-on) again.

7 · Campaign Editor: the campaigns

  1. TerrainTool top bar → Campaign Editor (it opens on the project). The right list shows the old add-on's .cam and .tac files; orange = units still to convert.
  2. Open one file (double-click) → toolbar Convert unit types.... In the window select the files (all of them) → Analyze selected files. Then the three tabs:
    • 1 · Vehicles: for each vehicle BMS 4.38 does not have, choose what replaces it. Suggest only equipment of the same producer keeps Western for Western; Hide unit types that stay the same, Show also the vehicles that exist in BMS 4.38.
    • 2 · Unit types: the BMS 4.38 unit type for each old one (change it if you want).
    • 3 · Weapons: aircraft weapons BMS 4.38 does not have: replace or remove.
    Save choices, then Convert selected files. Done once per file.
  3. Start window → Apply object changes: brings every campaign up to date with the objectives of step 6 (units on moved airbases, links).
  4. Open each campaign: Validate, fix the errors (double-click a row to see it), Station ILS... to check TACAN and ILS against the new runways, Save (into the project's CampaignEdits, never into BMS).

8 · Tab 8 · Build theater

  1. TerrainTool → tab 8 · Build theater → Refresh. Every row should be Ready; the button on a row goes where that part is made.
  2. Theater name in BMS: check it. Tick First re-make the 2D map if it is missing or older than the terrain.
  3. Build theater. Read Report of the last build and the Theater definition (.tdf) of the build. Open Output\Install shows the result.

9 · Install into BMS

  1. Close BMS.
  2. TerrainTool tab 9 · Install into BMS → Install everything... → confirm. Terrain and water maps, photoreal tiles, objects and the .tdf, UI art and Sim are copied; every replaced file goes to Output\BmsBackup\<date>.
  3. Campaign Editor start window → Install campaign files into BMS... → confirm. This is the only button that copies the campaign files (.cam, .tac, CampObjData.XML, stations+ils.dat).
  4. TerrainTool tab 9 → Check the terrain installed in BMS.

10 · First start in BMS and the campaign terrain

  1. Start BMS, choose the new theater in the Launcher, enter the UI. The first start rebuilds the terrain caches and takes longer.
  2. Start a campaign once (until the map appears), then quit BMS: BMS has now written its campaign terrain cache for the new terrain.
  3. Campaign Editor → Campaign terrain (.thr)... → Build from the New Terrain → compare Current .thr and New .thr (from the New Terrain) → Save.
  4. Check ground links: links blocked by water (bridges missing) are listed and written to ground_links_blocked.csv; fix them in the Objective editor (bridges, links). Ground units in water...: units standing in water, moved to land after you confirm.
  5. Objective Studio → Run Objects (from the old add-on) again (the bridge cells now use BMS's cache) → Campaign Editor → Apply object changes → Save.
  6. Close BMS, then Install objects... (tab 9 or Install objects into BMS... in Objective Studio) and Install campaign files into BMS....
Order mattersRun Check ground links and Ground units in water... only after BMS has made its campaign terrain cache for the new terrain (step 10.2). On an older cache the results are wrong; the editor ignores a cache older than the theater's grid and says so in the log.

11 · Check in flight

  1. Create a new Tactical Engagement (old TE missions made on the 4.37 grid keep the old positions) and take off from a Main airbase.
  2. Check the runway on the photoreal, the DED latitude/longitude against the real airport, ILS and TACAN.
  3. Record an ACMI and open it in Tacview: the aircraft must be on the real runway.
  4. Fly the campaign for a few minutes: ground units move, SAMs are on their sites (Check SAM systems & positions in the Sim Editor lists the problems).

12 · After a BMS update (e.g. 4.38.1 → 4.38.2)

  1. Objective Studio → Run Objects (from the old add-on): the objects are rebuilt on the new BMS database. If a COPY line of DbEdits now collides, use the next free number as the message says.
  2. If BMS changed a Sim file that is also in SimOverrides, merge BMS's new values into your copy.
  3. TerrainTool → Build theater; close BMS; tab 9 → Install objects... and Install theater Sim....
  4. Start BMS and check the log and a flight.
Going backEvery install can be undone: TerrainTool tab 9 → Restore a backup..., Objective Studio → Restore a backup..., Campaign Editor → Backups.... Restore newest first. Remove from BMS's theater list... hides the theater from the Launcher.

16Troubleshooting

ProblemWhat to do
A program does not startInstall the .NET 8 Desktop Runtime x64. If the suite is inside Program Files, move it to a folder you can write to.
BMS NOT FOUNDClick the chip in the main menu and choose the BMS Data folder (the one with Terrdata).
A theater is missing or "cannot be opened"The programs read BMS's theater list; a theater whose definition points to folders that do not exist cannot be opened. Check it in BMS's theater selection.
Install refused or files not updatedBMS is running (chip BMS RUNNING): close it and install again.
The change does not show in BMSRestart BMS. For objects, check that you pressed Build objects before Install.
Something went wrong after an installUse Restore a backup... in the program that installed (newest first), or put back your own copy of the Data folder.
3D view is slow or blankModel Editor: untick Shadows and Normal maps, or untick DirectX (PBR) for the classic view.
A program closed by itselfLook for an errors.log next to the program's exe and send it with a description when you report the problem.

Reporting a problem

Open an issue on the project's GitHub page with: what you did, what you expected, what happened, the theater, and the errors.log or a screenshot.
